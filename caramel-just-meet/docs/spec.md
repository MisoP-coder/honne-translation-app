# 極限！カラメル・ジャスト・ミート 仕様書

スマホだけで遊べる、プリンの頂点にカラメルを乗せ続けるタイミングゲーム。
Expo (React Native) + TypeScript で作る。iOS / Android（Expo Go）とブラウザで動く。

## 1. ゲーム概要

| 項目 | 内容 |
| --- | --- |
| ジャンル | ワンタップのタイミングゲーム |
| 操作 | 画面のどこかをタップするだけ |
| 目的 | 左右に揺れるプリンの頂点に、カラメルを1滴ずつ乗せ続ける |
| 終わる条件 | 1回でも頂点から大きくズレたら、カラメルが滑り落ちてゲームオーバー |
| 画面の向き | 縦 |

### 2.1 タイトル画面
- タイトルロゴ、ぷるぷる揺れるプリンのアニメーション、遊び方の説明。

- 画面下部にお皿に乗ったプリン。左右に不規則に揺れる。
- 未プレイ状態では「タップでカラメル投下！ プリンの頂点を狙え」と案内を出す。
- 背景は、光の当たった壁と木のテーブル（SVG）。

- 連続数に応じた称号（§5）。
- ボタン：「𝕏 でシェア」「もう一回」「世界ランキング」「タイトルへ」。

### 2.4 世界ランキング画面
- 上位20人を「順位・国旗・名前・最高連続数・スコア」で表示。1〜3位はメダル。

## 3. ゲームのルール

### 3.1 プリンの揺れ
- 周波数の違う3つのサイン波を重ね、さらに振れ幅をゆっくり変化させて「不規則なぷるぷる」にする。
- 周波数・位相はゲーム開始ごとに乱数で決まる（シード付き乱数なので、同じシードなら同じ揺れ方）。
- 連続成功数が増えるほど揺れが速くなる：速度倍率 = `min(1 + 連続数 × 0.05, 2.6)`。
- 振れ幅は画面幅の28%まで。プリンが画面からはみ出さないよう上限をかける。
- 速く動いているときほどプリンが傾き・つぶれる（見た目だけ。判定には影響しない程度に控えめ）。

### 3.2 カラメルの落下
- タップした瞬間にカラメルが1滴、容器から真下に落ち始める。
- 落下は等加速度運動。頂点に届くまで約0.6秒（画面サイズによらず一定）。
- 落下中・滑り落ち中・ゲームオーバー後のタップは無視する（同時に落ちるのは1滴だけ）。

### 3.3 判定
着地した瞬間の「カラメルの x − プリン中心の x」（ズレ）で判定する。
着地の瞬間はフレームの途中でも計算で求めるので、フレームレートが違っても判定は変わらない。

| 判定 | 条件（プリン頂点の半幅 = W） | 結果 |
| --- | --- | --- |
| JUST MEET!! | ズレ ≤ W × 0.22 | 成功。300点 + 連続ボーナス |
| GOOD | ズレ ≤ W × 0.75 | 成功。100点 + 連続ボーナス |
| ずるっ… | それより大きい | 失敗。滑り落ちてゲームオーバー |

- 連続ボーナス = それまでの連続数 × 10点。
- 成功するとプリンの上のカラメルが少しずつ厚くなり、横にたれる。
- 失敗するとカラメルがズレた側に約0.9秒かけて滑り落ち（かすりもしなければ真下に落ち）、そのあとゲームオーバー表示になる。

### 3.5 演出

**成功時**
- プリン本体が底を支点に「ぶるん！」と弾む（いったんつぶれて、伸びて、揺れながら戻るバネ）。JUST MEET は大きく、GOOD は控えめ。
- プリンの頂点から星と光の粒が上向きに飛び散り、重力で落ちながら消える。衝撃波のリングも広がる。
- コンボが増えるほど派手になる。

| コンボ | 粒の数（JUST MEET / GOOD） | 色 | リング（JUST MEET） |
| --- | --- | --- | --- |
| 0〜4 | 16〜24 / 8〜12 | 金・白 | 1本 |
| 5〜9 | 26〜34 / 13〜17 | 金・オレンジ・ピンク | 2本 |
| 10〜14 | 36〜44 / 18〜22 | 虹色 | 2本 |
| 15〜 | 最大76 / 最大38（30コンボで頭打ち） | 虹色 | 3本 |

- 粒は速さと大きさもコンボに応じて増す。同時に出すのは最大160個まで。
- 2コンボ以上で、画面中央に「〇〇 COMBO!!」を斜めに大きくポップ表示する。色は 2〜4：白、5〜9：オレンジ、10〜19：金、20〜：ピンク。コンボが増えるほど大きくなるが、画面からはみ出さない大きさに抑える。
- 10コンボ以上の JUST MEET では、画面が一瞬金色に光る。

**失敗時**
- 画面全体（スコア表示も含む）が上下左右に激しく揺れ（約0.4秒で収まる）、一瞬白く光る。
- 滑り落ちるのに合わせて、画面が一気にセピア（古い写真のような暗めの茶色）に変わり、四隅が暗くなる。ゲームオーバー表示の後ろもセピアのまま。
- セピア化は CSS の filter ではなく、描く色そのものを変換している（スマホでも同じ見た目にするため）。

### 3.4 記録
- スコアと最高連続数は端末（AsyncStorage）に保存し、それぞれ別々に最高値を更新する。
- 「NEW RECORD」はスコアがハイスコアを上回ったとき。

## 4. X（旧Twitter）シェア

ゲームオーバー画面の「𝕏 でシェア」で、X の投稿画面を開く（`Linking.openURL`）。

- URL：`https://x.com/intent/tweet?text=<本文をURLエンコード>`
  - X アプリが入っていればユニバーサルリンクでアプリが開き、なければブラウザで開く。
- 本文（`〇〇` は連続数、称号は §5）：

```
【極限！カラメル・ジャスト・ミート】プリンの頂点にカラメルを〇〇連続で乗せた！ 称号：[称号] #カラメルジャストミート
```

- 開けなかった場合もアプリは落ちない。

## 6. 世界ランキング（モック）

今はバックエンドなしで、フロントエンドだけで動くモック。

- `RankingRepository`（`src/ranking/types.ts`）がランキングの窓口。
  - `fetchTop(limit)`：上位の記録を取る
  - `submit(record)`：自分の記録を送る
- 今は `MockRankingRepository` が20人分のダミーデータを返す（0.4秒の待ち時間つき）。
- 画面側で自分のハイスコアを混ぜて順位を付ける（`rankWithMe`）。
  - 並び順：スコアが高い順 → 同点なら連続数が多い順。
  - スコアも連続数も同じなら同じ順位（自分はその後ろに並ぶ）。
  - スコア0は載せない。
- プレイヤー名は今は「あなた」で固定。

### Supabase に繋ぐとき
1. `RankingRepository` を実装した `SupabaseRankingRepository` を作る。
2. `App` の `rankingRepository` に渡す（未指定ならモックが使われる）。
3. テーブル案：`scores (id uuid, player_name text, country text, score int, combo int, created_at timestamptz)`。
   不正なスコアを防ぐため、送信は Edge Function 経由にしてスコアの上限チェックを入れる。

## 7. 構成

```
caramel-just-meet/
├── App.tsx                    画面の切り替え・ハイスコアとランキングの受け渡し
├── docs/spec.md               この仕様書
├── src/
│   ├── game/engine.ts         ゲームエンジン（揺れ・落下・判定・スコア。描画から独立した純粋関数）
│   ├── game/rng.ts            シード付き乱数
│   ├── game/titles.ts         称号
│   ├── game/particles.ts      キラキラ（星・光の粒・リング）の発生と動き
│   ├── share/xShare.ts        X シェア文とURL
│   ├── ranking/               ランキングの型・モック
│   ├── storage/highScore.ts   ハイスコアの保存
│   ├── hooks/                 ゲームループ（requestAnimationFrame）・ハイスコア
│   ├── theme/tone.ts          セピア化の色変換
│   ├── components/            SVG のプリン・雫・容器・背景、キラキラ、COMBO 表示、ゲームオーバー表示など
│   └── screens/               タイトル・ゲーム・ランキング
└── __tests__/                 テスト（Jest + React Native Testing Library）
```

### 描画とアニメーション
- ゲームの進行は `requestAnimationFrame` で毎フレーム `step(state, config, dt)` を呼んで進める（1フレーム最大1/30秒）。
- キラキラとセピア化は、ゲームと同じループで毎フレーム計算する。
- 判定の文字・COMBO 表示・「ぶるん！」・画面の揺れと光・ゲームオーバー表示・タイトルのプリンは React Native の `Animated` で動かす。
- 画面サイズは `onLayout` で測り、それに合わせてプリンの大きさや落下距離を決める。
- タップは押した瞬間に反応させたいので、`Pressable` ではなくレスポンダー（`onResponderGrant`）を使う。

## 8. テスト

`npm test` で以下を確認する。

- エンジン：揺れが範囲内に収まる・同じシードで同じ揺れ・速度の上限・落下時間・判定の境界・スコアとボーナス・ゲームオーバーまでの流れ・フレームレートに依存しない判定。
- シェア：定型文、URLエンコード、`Linking.openURL` の呼び出しと失敗時の扱い、称号。
- ランキング：自分の記録の差し込み位置、同順位、スコア0の扱い、モックの待ち時間、ハイスコアの保存・更新。
- 演出：キラキラの数・リング・色がコンボで増えること、飛び散って消えること、COMBO 表示の出る条件と大きさ、セピア化の色と進み方、SVG プリンの描画。
- 画面：ゲームオーバー表示のボタン、ランキング画面の表示、タップで落下→判定、画面遷移。
