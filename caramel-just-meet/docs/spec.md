# 極限！カラメル・ジャスト・ミート 仕様書

スマホだけで遊べる、プリンの頂点にカラメルを乗せ続けるタイミングゲーム。
Expo (React Native) + TypeScript で作る。iOS / Android（Expo Go）とブラウザで動く。

## 1. ゲーム概要

| 項目 | 内容 |
| --- | --- |
| ジャンル | ワンタップのタイミングゲーム |
| 操作 | 画面のどこかをタップするだけ |
| 目的 | 左右に揺れるプリンの頂点に、カラメルを1滴ずつ乗せ続ける |
| 終わる条件 | 1回でも頂点から大きくズレたら、カラメルが滑り落ちてゲームオーバー |
| 画面の向き | 縦 |

## 2. 画面と遷移

```
タイトル ──スタート──▶ ゲーム ──ミス──▶ ゲームオーバー（ゲーム画面に重ねて表示）
   │                    ▲                 │
   │                    └───もう一回───────┤
   ├──世界ランキング──▶ ランキング ◀─────────┤
   ◀──────────もどる────────┘               │
   ◀──────────────タイトルへ────────────────┘
```

### 2.1 タイトル画面
- タイトルロゴ、ぷるぷる揺れるプリンのアニメーション、遊び方の説明。
- 自分のハイスコア・最高連続数と、そこから決まる称号を表示。
- ボタン：「スタート」「世界ランキング」。
- 背景はパチンコ・お祭り風（Canva で作った背景イラストを元に SVG で描き直したもの）。
  - ゆっくり回る放射線、プリンを照らすスポットライト、きらめく紙吹雪・星、カラメルの雫、四隅の網点、ふちの暗がり。
  - 「極限！」は傾けた赤いリボン。タイトルと「スタート」はどくんどくんと脈打つ。
  - 背景がにぎやかなので、遊び方は白いカード、ハイスコアは濃い茶色の帯に載せて読みやすくする。
  - 端末の「視差効果を減らす」がオンなら、放射線と紙吹雪は動かさない。

### 2.2 ゲーム画面
- 上部の表示：SCORE（今回のスコア）／連続（今回の連続成功数）／BEST（ハイスコア）。
- 画面上部中央にカラメルの容器。カラメルは必ずここから真下に落ちる。
- 画面下部にお皿に乗ったプリン。左右に不規則に揺れる。
- 未プレイ状態では「タップでカラメル投下！ プリンの頂点を狙え」と案内を出す。
- 背景は、光の当たった壁と木のテーブル（SVG）。

### 2.2.1 見た目（SVG）
`react-native-svg` で描く。

| 部品 | 表現 |

### 2.2.2 一時停止
- 上部の右端に一時停止ボタン（⏸）。プレイ中（カラメルが滑り落ちていない間）だけ押せる。
- 一時停止中はゲームが完全に止まる（プリンの揺れ・落下中のカラメルも止まり、タップも効かない）。BGM もその場で止まる。
- 一時停止メニュー：今の連続数とスコア、「つづける」「サウンド設定」「はじめからやり直す」「タイトルへ」。
  - サウンド設定はタイトル画面と同じもの。閉じると一時停止メニューに戻る。一時停止中に設定を変えても BGM は鳴り出さない。
  - やり直す・タイトルへ戻ると、そのプレイの記録（ハイスコア・ランキング）は残らない。
- 「つづける」を押すと「3, 2, 1」と大きく数えて（1 つ 0.6 秒）から再開する。BGM は止めたところから続きが流れる（一時停止中に BGM をオフ→オンにしたときは頭から）。
- アプリが裏に回ったとき（電話・通知・ホームボタン、ブラウザでタブを切り替えたとき）は自動で一時停止する。

### 2.3 ゲームオーバー表示
- 「GAME OVER」、今回の連続数とスコア、JUST MEET の回数、ハイスコア。
- ハイスコア更新時は「★ NEW RECORD ★」。
- 連続数に応じた称号（§5）。
- ボタン：「𝕏 でシェア」「もう一回」「世界ランキング」「タイトルへ」。

### 2.4 世界ランキング画面
- 上位20人を「順位・国旗・名前・連続数・スコア」で表示。1〜3位はメダル。自分の行は色付きで強調する。
- 自分が上位20人に入らないときは、リストの下に自分の行（順位付き）を表示。
- 下の欄で名前を決めて、自己ベストを登録する（§6）。
  - まだ記録がないとき：「まずはプレイして記録を作ろう！」。
  - 登録済み：「〇〇 は世界 N 位！」と「名前を変える」ボタン。
  - 名前・国旗・スコアが世界中に公開されることを書いておく。
- 誰も登録していないときは「まだ誰も登録していません。一番乗りのチャンス！」。
- 読み込み中はくるくる、失敗したら「ランキングを読み込めませんでした」。
- サーバーの設定がないとき（サンプル表示）は「※ いまはサンプル表示です」と出す。

## 3. ゲームのルール

### 3.1 プリンの揺れ
- 周波数の違う3つのサイン波を重ね、さらに振れ幅をゆっくり変化させて「不規則なぷるぷる」にする。
- 周波数・位相はゲーム開始ごとに乱数で決まる（シード付き乱数なので、同じシードなら同じ揺れ方）。
- 連続成功数が増えるほど揺れが速くなる：速度倍率 = `min(1 + 連続数 × 0.04, 2.3)`。
- 振れ幅は画面幅の28%まで。プリンが画面からはみ出さないよう上限をかける。
- 速く動いているときほどプリンが傾き・つぶれる（見た目だけ。判定には影響しない程度に控えめ）。

### 3.2 カラメルの落下
- タップした瞬間にカラメルが1滴、容器から真下に落ち始める。
- 落下は等加速度運動。頂点に届くまで約0.6秒（画面サイズによらず一定）。
- 落下中・滑り落ち中・ゲームオーバー後のタップは無視する（同時に落ちるのは1滴だけ）。

### 3.3 判定
着地した瞬間の「カラメルの x − プリン中心の x」（ズレ）で判定する。
着地の瞬間はフレームの途中でも計算で求めるので、フレームレートが違っても判定は変わらない。

| 判定 | 条件（プリン頂点の半幅 = W） | 結果 |
| --- | --- | --- |
| JUST MEET!! | ズレ ≤ W × 0.3 | 成功。300点 + 連続ボーナス |
| GOOD | ズレ ≤ W（見えている頂上に雫の中心が乗っていれば） | 成功。100点 + 連続ボーナス |
| ずるっ… | それより大きい | 失敗。滑り落ちてゲームオーバー |

- 連続ボーナス = それまでの連続数 × 10点。
- 成功するとプリンの上のカラメルが少しずつ厚くなり、横にたれる。
- 失敗するとカラメルがズレた側に約0.9秒かけて滑り落ち（かすりもしなければ真下に落ち）、そのあとゲームオーバー表示になる。

### 3.5 演出

**成功時**
- プリン本体が底を支点に「ぶるん！」と弾む（いったんつぶれて、伸びて、揺れながら戻るバネ）。JUST MEET は大きく、GOOD は控えめ。
- プリンの頂点から星と光の粒が上向きに飛び散り、重力で落ちながら消える。衝撃波のリングも広がる。
- コンボが増えるほど派手になる。

| コンボ | 粒の数（JUST MEET / GOOD） | 色 | リング（JUST MEET） |
| --- | --- | --- | --- |
| 0〜4 | 16〜24 / 8〜12 | 金・白 | 1本 |
| 5〜9 | 26〜34 / 13〜17 | 金・オレンジ・ピンク | 2本 |
| 10〜14 | 36〜44 / 18〜22 | 虹色 | 2本 |
| 15〜 | 最大76 / 最大38（30コンボで頭打ち） | 虹色 | 3本 |

- 粒は速さと大きさもコンボに応じて増す。同時に出すのは最大160個まで。
- 2コンボ以上で、画面中央に「〇〇 COMBO!!」を斜めに大きく表示する（出し方は 3.6）。色は 2〜4：白、5〜9：オレンジ、10〜19：黄色、20〜：虹色。コンボが増えるほど大きくなるが、落ち着いたときに画面からはみ出さない大きさに抑える。
- 10コンボ以上の JUST MEET では、画面が一瞬金色に光る。

**失敗時**
- 画面全体（スコア表示も含む）が上下左右に激しく揺れ（約0.4秒で収まる）、一瞬白く光る。
- 滑り落ちるのに合わせて、画面が一気にセピア（古い写真のような暗めの茶色）に変わり、四隅が暗くなる。ゲームオーバー表示の後ろもセピアのまま。
- セピア化は CSS の filter ではなく、描く色そのものを変換している（スマホでも同じ見た目にするため）。

### 3.4 記録
- スコアと最高連続数は端末（AsyncStorage）に保存し、それぞれ別々に最高値を更新する。
- 「NEW RECORD」はスコアがハイスコアを上回ったとき。
- ハイスコアを出したゲームの連続数も保存する（ランキングに登録するため）。前のバージョンのデータはスコアから求める。

### 3.6 バカゲー・パチンコ風の演出

**文字**
- 「JUST MEET!!」「GOOD!」「ずるっ…」「〇〇 COMBO!!」「GAME OVER」は、太い黒の縁取りと、右下に押し出した立体的な影を付ける。
  スマホの文字には縁取りの機能がないため、同じ文字を上下左右斜めにずらして重ねて描いている。
- 「〇〇 COMBO!!」は「ドーン！」と出る：
  1. 画面の手前に向かって一気に拡大する（最大 1.35〜2.05 倍。コンボが多いほど大きい）。
  2. 上から落ちてきてバウンドしながら等倍に戻る（コンボが多いほど激しく跳ねる。30コンボで頭打ち）。
  3. 0.5秒ほど止まって読ませる。
  4. こちらに飛んでくるように拡大しながら消える。

**背景（コンボ演出）**
- 10コンボ以上：プリンを中心に漫画の集中線を薄く表示し、ゆっくり回す。
- 20コンボ以上：集中線が虹色になって速く回り、背景全体が虹色に染まる。プリンの周りに虹色の後光が出る。
  - 色相は速く回すが、画面全体の明るさの脈動は 1 秒に 2.4 回に抑える（1 秒に 3 回以上の全画面の点滅は、光に敏感な人の発作を招くおそれがあるため）。
- ミスした瞬間に背景演出は止まる。

**ゲームオーバー**
- 「ずるっ…」は上からドスンと落ちてきて、その場でガタガタ震え続ける。
- 「GAME OVER」も赤い縁取り文字でガタガタ震え続ける。
- セピア化に合わせて、古いテレビの砂嵐（白黒の粒が 0.07 秒ごとにチラつく）、走査線、上から下へ流れる明るい帯を画面全体に薄く重ねる。

**プリンの顔**
- プリンの正面に、ツヤのある黒目・ピンクのほっぺ・にっこり口のかわいい顔を描く。
- 顔はバネでつながっているように動く。プリンが揺れて加速すると、顔は慣性で置いていかれ、少し遅れてプルプルしながら戻る。横にずれると少し持ち上がる。ずれは頂上の半幅の 24% まで。
- ミスすると、白目の小さな目とぐにゃぐにゃの口になる（ほっぺは消える）。

### 3.7 BGM と効果音

音はすべて `scripts/generate_sounds.py` で波形から合成した自作の音源で、`assets/sounds/` に同梱する（WAV・22.05kHz・モノラル、合計約 2.9MB）。
ネットから読み込まないので、オフラインでも鳴り、通信待ちで音が遅れることもない。BGM の曲はどちらも著作権の切れたベートーヴェンの作品を独自に演奏したもの。

| 場面 | 音 |
| --- | --- |
| タイトル・ランキング | BGM：交響曲第5番「運命」冒頭（弦・金管・ティンパニの無駄に壮大なオーケストラ風、約19秒ループ） |
| ゲーム中 | BGM：交響曲第9番「歓喜の歌」（お祭り風チップチューン＋和太鼓、BPM160、24秒ループ） |
| カラメル投下 | 「ヒュゥゥン」（高い音から下がる口笛＋風切り音、0.6秒＝落下時間と同じ） |
| JUST MEET | 「ピキーン！」（金属的な FM 音＋キラキラ）。1〜8コンボで長音階（ド〜ド）を1音ずつ上がり、8コンボ以上は最高音のまま |
| 10コンボ以上の JUST MEET | 上に加えて、パチンコのリーチ風「キュイィィン」を重ねる |
| 20コンボ以上の JUST MEET | リーチ音の代わりに「確定！」音（うなり＋長調の和音のベル） |
| GOOD | 「ポロン」 |
| ミス | BGM をその瞬間にピタッと止め、拍子木「カッ…カーン」→ おりんの「チーン…」 |

- 再生には `expo-audio` を使う（`expo-av` は SDK 57 には含まれないため）。
- 起動時に全部の音のプレイヤーを作って読み込んでおき、鳴らす瞬間に読み込まない。アプリを閉じるときに全部解放する。
- BGM は同時に1曲だけ。効果音は毎回頭から鳴らす。音が読み込めなくてもゲームは止まらない。
- 別のアプリ・別のタブに移ったり、画面を消したり、ブラウザを閉じたりしたら、どの画面でも BGM と効果音を止める。戻ったら BGM を続きから流す（プレイ中なら一時停止のままにして、「つづける」で再開）。
- タイトル画面右上の「サウンド」ボタンで設定画面を開き、BGM と効果音をそれぞれ別に設定できる。
  - オン・オフのスイッチ（BGM をオフにすると BGM だけが止まり、効果音は鳴る。逆も同じ）
  - 音量ゲージ（0〜100%、10% 刻み。ゲージをタップするか、なぞって変える）。BGM の音量は流れている曲にすぐ反映し、効果音は指を離したときにその音量で「ピキーン！」を試し鳴らしする
  - 実際の音量は「音ごとの基本の音量 × BGM / 効果音の音量」。音量 0% はオフと同じ
  - BGM をオフにしている間に画面が変わっても、オンに戻すとその画面の曲が流れる
  - 設定は端末に保存され、次に開いたときも使われる（初期値は両方オン・80%）
  - BGM も効果音も鳴らない設定のときは、ボタンの表示が 🔊 から 🔇 に変わる
- iPhone ではマナーモード（消音スイッチ）中は鳴らない（OS の設定に従う）。
- ブラウザは画面に触れるまで音を出させてくれない（開いた直後に BGM を流すことはできない）。
  - タイトル画面に「🔊 画面をタップすると BGM が流れます」と出し、最初のタップで BGM を鳴らし始める（BGM がオフのときは出さない）。
  - ブラウザが再生を認めるのは指を「離した」とき（pointerup / touchend / click / キー入力）。指が触れた瞬間（pointerdown）に鳴らそうとすると、iPhone の Safari などでは断られる。
  - 鳴らせなかったときのために、タップのたびに BGM の再生を試す（鳴っている最中なら何も起きない。ゲームオーバーで止めた BGM や一時停止中は鳴らさない）。

## 4. X（旧Twitter）シェア

ゲームオーバー画面の「𝕏 でシェア」で、X の投稿画面を開く（`Linking.openURL`）。

- URL：`https://x.com/intent/tweet?text=<本文をURLエンコード>&url=<ゲームのURL>`
  - ゲームの URL は `EXPO_PUBLIC_SITE_URL`、なければブラウザ版で開いているページ。どちらもなければ付けない。
  - URL を付けると、投稿にゲームのカード（OGP 画像）が出る。
  - X アプリが入っていればユニバーサルリンクでアプリが開き、なければブラウザで開く。
- 本文（`〇〇` は連続数、称号は §5）：


- 開けなかった場合もアプリは落ちない。

## 6. 世界ランキング（Supabase）

- データは Supabase（Postgres）に置く。テーブルと関数は `supabase/schema.sql`。
- アプリは Supabase の REST（`/rest/v1/rpc/<関数名>`）を `fetch` で呼ぶだけ（`src/ranking/supabaseRanking.ts`）。
- 接続先は環境変数 `EXPO_PUBLIC_SUPABASE_URL` と `EXPO_PUBLIC_SUPABASE_ANON_KEY`（`src/config.ts`）。
  - どちらかがなければ、サンプルのランキング（`MockRankingRepository`、ダミー20人）で動く。

### プレイヤー
- 端末ごとに、秘密の合言葉（`player_id`、ランダムな UUID）を作って端末に保存する。記録の持ち主はこれで見分ける。
- ランキングに出すのは別の公開 ID（`public_id`）だけ。合言葉は他の人には見えない。
- 名前は 1〜12 文字（空白はまとめる）。国旗は端末の言語設定の地域から決める（地域がなければ 🌏）。
- 名前を登録すると自己ベストが送られる。その後は自己ベストを更新するたびに自動で送る。

### 並び順
- スコアが高い順 → 同点なら連続数が多い順。どちらも同じなら同じ順位。

### サーバー側の守り
- テーブルは RLS を有効にしてポリシーなし。直接の読み書きはできず、決められた関数だけ呼べる。
  - `caramel_top(limit)`：上位（最大100人）を順位付きで返す。合言葉は返さない。
  - `caramel_rank(score, combo)`：その記録が何位か。
  - `caramel_submit(player_id, name, flag, score, combo)`：登録・更新。自己ベストより低い記録ではスコアは下がらず、名前と国旗だけ変わる。
- ゲームのルールで出せないスコアは断る（`100n + 5n(n−1)` から `300n + 5n(n−1)` まで 200 刻み。n は連続数）。
- 同じ人の送信は 2 秒に 1 回まで。
- ブラウザで動くゲームなので、ずるを完全に防ぐことはできない。ありえない点数を弾くところまで。
- 名前の自動チェックはしない。よくない名前は Supabase の管理画面から手で消す。

### 描画とアニメーション
- ゲームの進行は `requestAnimationFrame` で毎フレーム `step(state, config, dt)` を呼んで進める（1フレーム最大1/30秒）。
- キラキラとセピア化は、ゲームと同じループで毎フレーム計算する。
- 判定の文字・COMBO 表示・「ぶるん！」・画面の揺れと光・ゲームオーバー表示・タイトルのプリンは React Native の `Animated` で動かす。
- 画面サイズは `onLayout` で測り、それに合わせてプリンの大きさや落下距離を決める。
- タップは押した瞬間に反応させたいので、`Pressable` ではなくレスポンダー（`onResponderGrant`）を使う。
