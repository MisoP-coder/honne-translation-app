## 詰まった10箇所

### 1. デプロイ成功。なのに404

Vercel で「Congratulations!」と出たので URL を開いたら **404** でした。設定を疑って1時間使いましたが、原因は別のところにありました。

**GitHub の main ブランチに、README.md しか入っていなかった**のです。

コードはプルリクエストの中にあって、マージしていませんでした。Vercel は main を見て公開するので、そこに何も無ければ404になります。

**抜け方**: GitHub でプルリクエストを開き、緑の Merge ボタンを押す。それだけでした。

> **教訓**: Vercel の「成功」は「main ブランチの内容を配った」という意味しかありません。main に何が入っているかは、別途 GitHub で確認する必要があります。

### 2. `No Output Directory named "public" found`

次に出たのがこれです。ビルドが途中で止まりました。

原因は、**Vercel がこのアプリを Next.js だと認識していなかった**ことです。プロジェクトを取り込んだ時点で main に `package.json` が無かったため(1番の状態です)、種類の判定が別のものに固定されていました。

**抜け方**: リポジトリのルートに `vercel.json` を置きます。

```json
{ "framework": "nextjs" }
```

ダッシュボードの設定画面から直すこともできますが、**スマホだとその設定項目を探すのがとにかく大変**でした。ファイルを1つ置くほうが速いです。

> **教訓**: スマホでの開発では、「設定画面をいじる」より「設定ファイルを置く」ほうが圧倒的に楽です。ダッシュボードはスマホ向けに作られていません。

### 3. 新規登録を押したら `Invalid path specified in request URL`

アプリの画面は出たのに、アカウントが作れませんでした。

原因は、**Supabase の接続先 URL の貼り間違い**です。こうコピーして貼っていました。

```
https://xxxxx.supabase.co/rest/v1/
```

正しかったのはこちらです。

```
https://xxxxx.supabase.co
```

`/rest/v1/` の部分は、API の入口を示す別の URL でした。Supabase の画面には似た URL が複数並んでいて、どれが Project URL なのか一目では分かりません。

### 4. 環境変数が保存できない

API キーを Vercel に登録しようとして、こう出ました。

```
Environment variables with a public framework prefix cannot use visibility: secret
```

**2段構えの罠**があります。

まず、`NEXT_PUBLIC_` で始まる変数は **Secret にできません**。これらはブラウザに埋め込まれる公開値なので、秘密にする意味がないからです。Type は **Config** を選びます。

さらに厄介なのが、**一度 Secret で保存した変数は、あとから Config に変更できない**ことです。

**抜け方**: 該当の変数を削除して、Config で作り直す。

逆に、本物の秘密(私の場合は Anthropic の API キー)は Secret のままにします。ブラウザに出てはいけない値なので、区別が必要です。

> **教訓**: 変数名の頭に `NEXT_PUBLIC_` が付いているかどうかで、扱いが変わります。付いていたら公開値、付いていなければ秘密です。

### 5. 直したのに、いつまでも反映されない

**これがいちばん長く苦しみました。**設定を直して、コードも直して、それでも画面が変わらない。

原因は2つありました。

**ひとつ目。Vercel には2種類の URL があります。**

- 本番の URL(短い。プロジェクト名だけ)
- **デプロイごとの URL**(長い。途中にランダムな文字列が入る)

私はデプロイごとの URL をブックマークしていました。この URL は「そのときのデプロイ」に固定されていて、永久に変わりません。**新しく直しても、古い画面をずっと見続けることになります。**

**ふたつ目。環境変数は、保存しただけでは反映されません。**値はビルドのときにアプリへ埋め込まれるので、保存後に再デプロイが必要です。

**抜け方**:

- Vercel の Domains に出ている**短い URL** を開く。ブックマークもそちらにする
- 環境変数を直したら、Deployments → 最新の「…」→ **Redeploy**

> **教訓**: 「直したのに変わらない」と思ったとき、**自分が見ている画面が古いのか、直した内容が届いていないのか**、まずどちらなのかを切り分けます。ここを飛ばすと無限に迷います。

### 6. ボタンが画面からはみ出す

「無料で始める」ボタンが、右端から少しはみ出していました。

原因は幅の計算方法です。リンクとして作ったボタンは、標準では「内側の余白を幅に含めない」計算をします。幅100%を指定した上に左右16pxずつ余白を足すと、**画面より32px大きくなります。**

**抜け方**: CSS に1行。

```css
* { box-sizing: border-box; }
```

> **教訓**: スマホでの見た目の崩れは、たいていこの幅計算が原因です。1箇所を直すより、この1行を最初から入れておくと事故が減ります。

### 7. メールの文面が、どうしても編集できない

アプリが送るパスワード再設定メールが英語のままでした。差出人も `Supabase Auth` で、どのアプリからのメールか分かりません。

Supabase の管理画面に文面の設定はあります。**でも、入力欄が触れませんでした。**

原因は、**無料プランで標準のメール送信を使っているあいだは、テンプレートの編集がロックされている**ことです。無料枠のメール送信がフィッシングメールの配信に悪用された件を受けた制限だそうです。

抜け方は2つあります。

1. 外部のメール送信サービス(Resend など)を登録する。ロックが外れます
2. **アプリ側で「英語のメールが届きます」と案内してしまう**

私は当面、後者にしました。送信直後の画面に「差出人は Supabase Auth、件名は Reset Your Password の英語のメールです」と出すようにしたら、実用上は困らなくなりました。

:::message
この制限にはもう一つ落とし穴があります。**標準のメール送信は1時間あたり2通まで**です。パスワード再設定・メールリンク・登録確認で、この2通を共用します。テスト中に「急に届かなくなった」のは、だいたいこれです。しかも**エラーが出ないまま沈黙する**ことがあります。
:::

> **教訓**: 直せない制限にぶつかったとき、「その制限を回避する」以外に「**制限があることを伝えてしまう**」という手があります。後者は5分で終わります。

### 8. 「特に問題なかったよ」がいちばん危ない

知人に何人か試してもらいました。返ってきたのは「特に問題なさそう」でした。

安心しかけたのですが、念のため利用状況を数える仕組みを入れてデータを見ました。

**相談まで到達していたのは、2人だけでした。**

頼まれて触った人は、詰まっても「自分の使い方が悪いのかな」と思って黙って離れます。悪気はまったくありません。そういうものです。

**抜け方**: 感想を聞くのをやめて、**行動を数えます。**

- 何人が登録したか
- そのうち何人が最後まで進んだか
- 2回以上使った人は何人か

段階ごとに人数を並べると、どこで人が落ちているかが一目で分かります。

> **教訓**: 「問題なかった」は、問題が無い証拠ではありません。**数字だけが本当のことを言います。**

### 9. 目玉の機能が、一度も動いていなかった

このアプリの売りは「**使うほど、その相手に合った予測になる**」ことです。結果を記録すると、それをもとに予測が変わります。

データを見たら、**その機能が発動した回数はゼロ**でした。

バグかと思って調べましたが、コードは正しく動いていました。原因は設計のほうにありました。

記録は、相談した「あと」に増えます。だから、こうなります。

```
1回目の相談 → 記録0件 → 一般論
            記録が1件に
2回目の相談 → 記録1件 → 一般論
            記録が2件に
3回目の相談 → 記録2件 → 一般論
            記録が3件に
4回目の相談 → ようやく発動
```

切り替えに3件必要な設計にしていたので、**同じ相手に4回相談しないと売りの機能に届かなかった**のです。

作った本人は到達していました。他の誰も到達していませんでした。

**抜け方**: 必要な件数を3件から2件に下げました。3回目で発動します。

> **教訓**: 「**何回使えばこの機能に届くか**」を数えてみてください。作った本人は何十回も触るので、絶対に気づけません。数えれば一瞬で分かります。

### 10. 独自ドメインが繋がらない(お名前.com)

最後の関門でした。取得したドメインをアプリに繋ぐ作業です。ここで2つ間違えました。

**ひとつ目。ホスト名の欄です。**

使いたい URL が `honne.misop-craft.com` なら、ホスト名に入れるのは **`honne` だけ**です。全部入れると `honne.misop-craft.com.misop-craft.com` というおかしなものができあがります。

**ふたつ目。Vercel は設定値を、末尾にドットを付けて表示します。**

```
xxxxx.vercel-dns-017.com.
```

この最後のドットは「完全なドメイン名」を示す DNS の記法です。**お名前.com の入力欄はドット無しが前提なので、付けると弾かれます。**

設定しても繋がらない場合、確認箇所がもう1つあります。お名前.com の「ネームサーバーの設定」で `01.dnsv.jp` 〜 `04.dnsv.jp` が入っているかを見てください。**ここが別のものだと、DNS レコードを設定しても無視されます。**

反映には数十分から数時間(最大24時間)かかります。**待つしかない時間があることは、最初から知っておいたほうが精神的に楽です。**

## スマホだけで進めるために効いたこと

画面の小ささが最大の敵でした。その中で効いた工夫を挙げます。

### 1. 設定はダッシュボードよりファイルで

さきほどの `vercel.json` のように、設定ファイルで済むならそちらにします。スマホのダッシュボードは、項目を探すだけで疲れます。

### 2. 管理画面は URL の直打ちで開く

Vercel も Supabase も、URL の末尾にパスを足せば目的の画面に直接飛べます。

| サービス | 足すパス | 行き先 |
| --- | --- | --- |
| Vercel | `/settings/domains` | ドメイン設定 |
| Supabase | `/auth/url-configuration` | 認証の URL 設定 |
| Supabase | `/auth/providers` | ログイン方法の設定 |
| Supabase | `/sql` | SQL エディタ |

**メニューを辿るより何倍も速いです。**

### 3. エラーは全文をスクショで送る

要約して伝えると、原因の特定が遅れます。長くても全部見せたほうが、一発で分かることが多いです。

### 4. 手順書を自分用に作っておく

同じ設定を2回目にやるとき、**前回どうしたか絶対に忘れています。**詰まって解決したら、その場で手順を書き残すようにしました。

実際、この記事の元になったのもその手順書です。
