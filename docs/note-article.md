## ⚠️ 差し替えが必要な箇所

体験談の具体的な部分は**架空のもの**です。Miso-P さんの名前で出す文章なので、実際の出来事に置き換えてください。特に次の5つは、事実と違う場合は必ず直してください。

| 記事の中の記述 | 確認 |
| --- | --- |
| 金曜の夕方に納期遅れが分かった | 実際にあった別の場面に |
| 下書きを7回書き直した / 30分固まった | 実感に近い数字に |
| 前の上司は経緯から話すと納得するタイプだった | 実際の対比があれば差し替え |
| 今の課長に途中で「で、結論は?」と遮られた | 実際に言われた言葉に |
| 同僚に相談したら愚痴に聞こえた | 心当たりがなければ削除 |

数字や場面が変わっても記事の骨格は崩れないので、上から順に自分の記憶に置き換えていけば大丈夫です。**思い出せない部分は、ぼかすか削ってください。** 作り話を足すより、短くなったほうが読まれます。

## 本文(ここをコピーしてください)

```
納期に間に合わないと分かったのは、金曜の夕方だった。

3日遅れる。今日のうちに課長に伝えないといけない。それは分かっている。
分かっているのに、メールの下書きを7回書き直して、まだ送れていなかった。

「申し訳ありません、納期が遅れそうです」——弱い。言い訳に聞こえる。
「納期を3日超過する見込みです」——冷たい。反省していないと思われる。
「ご相談したいことがあり」——何の話か分からない、と怒られる。

全部消して、また一行目から書き始める。時計を見たら30分経っていた。

伝える内容は、最初から決まっていた。遅れる。それだけだ。
30分悩んでいたのは、内容ではなく「言い方」だった。


■ 同じ内容なのに、相手によって正解が変わる

前の部署の上司は、経緯から話すと納得してくれる人だった。
「こういう事情があって、こうなって、それで今こうなっています」と順に説明すると、
最後には「なるほどね、じゃあこうしよう」と一緒に考えてくれた。

その調子で、今の課長に話した。

途中で遮られた。「で、結論は?」

あのときの空気を、まだ覚えている。
悪気があって言われたわけじゃない。ただ、この人は先に結論が欲しい人だった。
それだけの違いで、同じ誠実さが、同じようには伝わらなかった。

このとき気づいた。
「正しい伝え方」というものは、たぶん存在しない。
あるのは「この人に効く伝え方」だけだ。


■ でも、それを誰にも聞けない

同僚に「これ、どう伝えたらいいと思う?」と聞いたことがある。
話しているうちに、だんだん上司の愚痴のようになってきて、途中でやめた。
本当は言い方を相談したかっただけなのに。

ネットで「報連相 コツ」と調べると、出てくるのは一般論だった。
「結論から簡潔に伝える」。それは知っている。
知りたいのは、うちの課長が結論から聞きたい人なのかどうかだ。

AI に聞いてみたこともある。悪くない文章は出てきた。
ただ、その AI はうちの課長を知らない。
だから返ってくるのは、やっぱり一般論だった。

つまり、この悩みには「相手を知っている相談相手」が必要だった。
そして、そんな都合のいい相手はどこにもいなかった。


■ だから作った

「言いにくいことの翻訳」というアプリを作りました。

まず、上司を登録します。呼び名と、5つの質問に答えるだけ。
「指摘されたとき、冷静か感情的か」「結論から聞きたいか、経緯から聞きたいか」
——そういう、付き合っていれば自然と分かっていることです。

次に、状況を書きます。
「納期に3日遅れそうで、今日中に伝えないといけない」くらいの一文で十分です。

すると、トーンの違う言い方が3つ出てきます。
それぞれに、こんな予測がついています。

・信頼にどう響くか(向上 / 維持 / 悪化)
・場の温度がどうなるか(平常 / やや気まずい / 気まずい)
・なぜそう予測したのか

対面・電話・メール・チャットから伝え方も選べるので、
メールなら件名から、電話なら「いまお時間よろしいですか」から始まる文章が出ます。


■ いちばん作りたかったのは、この機能

伝えたあと、結果を記録できます。
「うまくいった」「様子見」「こじれた」の3択です。

これが2件たまると、一般論ではなく
**あなたとその上司の実績**をもとに予測するようになります。

こじれた言い方に似た案は避けるようになり、
うまくいったときのトーンを引き継ぐようになる。

なぜこれを作りたかったのか。

上司との付き合い方は、結局その人と過ごした経験からしか学べません。
私にもそういう蓄積はあったはずなのに、全部自分の頭の中にあるだけで、
次に同じ場面が来たときに活かせていなかった。

「前もこれで失敗したな」と思い出すのは、いつも送った後だった。

それを外に出しておける場所を作りたかった、というのが本音です。


■ 正直に書いておきます

出てくるのは、あくまで案です。
そのまま送らず、必ず自分で読み直してから使ってください。

上司との関係が良くなることを保証するものではありません。
最後に言葉を出すのは自分なので、判断はご自身でお願いします。

それから、これは報告や相談の言い方を考えるための道具です。
ハラスメントのような深刻な問題には向きません。
そういうときは、社内の相談窓口や公的機関、専門家に相談してください。


■ 9月30日まで無料です

https://honne.misop-craft.com

メールアドレスとパスワードだけで始められます。30秒くらいです。
入力した内容は自分のアカウントからしか見られませんし、
上司本人に通知が行くこともありません。

個人で作って個人で運営しているので、まずは9月30日まで無料で公開します。

使ってみて「ここが分かりにくかった」というところがあれば、
ぜひ教えてください。そこを直していきます。

送信ボタンの前で止まっている人に、届いたらうれしいです。
```

## 投稿したあとに

1. **X で note のリンクを投稿する** — アプリの URL を直接貼るより、記事を経由したほうが「なぜ作ったか」が伝わって試してもらえます
2. **記事の末尾に追記していく** — 反応や改善をあとから足すと、記事が育ちます
3. **コメントには返す** — note はコメントに反応があると読者との距離が縮まります

## 書き足すと強くなる部分

余力があれば、次のどれかを足すと記事の厚みが増します。

- **実際に出てきた候補文のスクリーンショット** — 「何が出てくるか」が一目で伝わります。文章で説明するより早いです
- **作るのにかかった時間や費用** — 個人開発のタグから来る読者が最も知りたい部分です
- **うまくいかなかった話** — 「最初は実績3件で切り替える設計にしたが、誰も到達しなかったので2件に下げた」のような失敗談は、成功譚より読まれます
